# 决策日志 · dsh-wallpaper

两轨记录：**已定**（本节，含依据）与**未做/待定**（末节）。

## D-01 形态：常驻插件，而不是临时 Cordis 插件

- **决定**：做成 npm 包 + `cordis.patch.yml`，挂进 `~/.dsh/profiles/web`。
- **依据**：用户选择「常驻插件：写进 ~/.dsh 的 web profile」。壁纸是观感设施，重启 DSH 后消失等于没做。
- **代价**：需要写profile 目录（在工作区沙箱之外），因此安装这一步需要一次放宽权限或由用户在终端执行；见 `INSTALL.md`。

## D-02 用量口径：只显示「本次会话」

- **决定**：面板只显示会话级用量，并提供会话下拉（默认当前会话）。
- **依据**：用户选择「只要本次会话」。宿主只折叠**内存中已加载**的会话（当前打开过的），不扫 80 份历史日志 —— 这正是「本次会话」的自然边界。
- **代价**：看不到跨会话累计（那是另一个功能，见「未做」）。

## D-03 数据来源：会话日志里的 `assistant/message.usage`

- **决定**：宿主读 `session.snapshotEvents()`，取 `assistant/message` 事件的 `usage`（`inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens` / `reasoningTokens`），模型取自 `request/header.header.config.model`（回退 `request/context.model`）。
- **依据**：实测确认这是唯一真实来源 —— DSH 不落盘任何「用量/账单」记录，`usage` 就挂在 assistant 消息事件上（`dsh-session` 类型里注释明确：「there is no separate usage record」）。宿主侧只服务端可读，浏览器侧读不到日志。
- **代价**：只统计已提交到日志的步骤；被中断且未生成消息的步骤不计（与官方账单口径一致，官方按请求计费、无消息则无 token）。

## D-04 金额：先做后删 —— 现在完全不显示消费

- **决定（本轮改定）**：**移除**金额。不估算、不显示、不提供单价表；面板只给日志真实记录的 token 计数与高峰/非高峰时段划分。
- **经过**：上一轮按用户选择做过一版「内置 DeepSeek 官方价目 + 按模型分别计价 + 标注估算」，用户看过后判断「感觉不太准」，要求删除。
- **依据**：这个判断是对的，而且理由比「感觉」更硬 —— 见 `dsh-wallpaper/README.md`「为什么没有金额」：官方调价（内置副本会静默过期）、法定节假日（本地无权威日历，而官方节假日算低谷）、计费时刻口径（供应商按请求时刻、日志只有事件时刻）。
- **代价**：用户看不到金额了。补偿是显示**高峰/非高峰的 token 划分**，它能解释「账单为何与 token 数不成正比」，但不假装成账单。
- **连带清理**：宿主不再返回 `costCNY` / `unitPrices` / `pricing`；`priceUsage()` 与 `PRICING` 一并删除；测试里的金额断言删除，改为断言「金额字段必须不存在」，防止哪天又漏回来。

## D-04b 高峰/非高峰划分：保留，但它只是时段，不是价格

- **决定**：保留「按每条记录自身的北京时间判定高峰/非高峰」这件事，显示为两行 token 数。
- **依据**：用户要删的是**金额**，不是这个事实。官方确实按北京时间周一至周五 09:00–12:00、14:00–18:00 计高峰，其余时段半价（本机日志里大段用量落在低谷）；只报 token 数而不报时段，会让「账单与 token 不成正比」显得毫无解释。
- **代价**：多两行数字。已确认面板不会因此出现空行（`client-syntax-check` 断言高峰/非高峰两行必须存在且有样式）。

## D-05 铺法：整页背景 + 一个面板

- **决定**：`lib/client.js` 往 `document.body` 插一层 `position:fixed; inset:0` 的壁纸层，只通过 `html.dsh-wallpaper-on` 这一个 class 开关；透明化用主题变量（`--dsw-alias-bg-base` / `--dsw-specific-sidebar-fill`）+ 给正文列加半透明压暗层，保证文字对比度。
- **依据**：用户选择「铺在整个 DSH 网页背景 + 一个面板负责换图与用量」。`shell.overlay` 是 click-through 浮层，面板必须自带 `pointer-events:auto`；用主题变量而不是硬编码颜色，才能跟随明暗主题。
- **代价**：涉及产品自身的 DOM 层级（`body > div` / `#root`），DSH 前端大改版时这一层选择器可能需要跟着改；功能本身（路由、数据、面板）不受影响。

## D-06 状态放 `~/.dsh/wallpaper/`，不放插件目录

- **决定**：配置 `~/.dsh/wallpaper/config.json`，上传的壁纸 `~/.dsh/wallpaper/wallpapers/`；`DSH_WALLPAPER_HOME` 可覆盖（测试脚本用）。
- **依据**：插件用 `link:` 安装（符号链接指向工作区），插件目录可能被重装/替换；用户选的壁纸不该因此丢。
- **代价**：多一个目录；卸载插件不会自动清它（README 里写明怎么删）。

## D-07 推送：SSE + 前端轮询兜底

- **决定**：`GET /dsh-wallpaper/api/events` 推 `usage` / `config` 帧；前端 EventSource 出错就退回 5s 轮询。宿主只在**有流打开**时才重算用量。
- **依据**：用量在流式输出时持续增长，纯轮询要么慢要么吵；而没开面板时不该有后台开销。
- **代价**：多一条长连接（本机 loopback）。

## D-08 安装需要一次放宽权限（不做静默绕过）

- **决定**：安装步骤写明 `dsh plugin --profile web add link:...`，需要写 `~/.dsh/profiles/web`；在会话沙箱里这属于工作区外，会以 `Read-only file system` 被拒。
- **依据**：本会话文件沙箱是 `workspace-write`（只允许写 `/home/atlaslinux/Wallpaper Plugin`）。实测 `mkdir ~/.dsh/wallpaper` 被拒。
- **代价**：安装由用户执行，或由我在获批后执行一次。

## D-09 配色：换的是**栏目**，不是整页（第 6 轮修正）

- **决定（改定）**：四套深蓝配色（深蓝默认 / 墨蓝 / 午夜青 / 石墨），通过重着色主题的
  `--dsw-static-neutral-bluish-*` 中性色阶实现 —— 编辑栏、会话列表、菜单、悬停态、插件表面全部跟着变；
  **壁纸本身不染色**。
- **依据**：用户第 6 轮明确「我说的调整 ui 的颜色是指这些栏目的 ui 颜色（编辑栏/会话列表…），不是指整体颜色」。
  第 4–5 轮我理解错了：往画面上叠了一层蓝色染色层，那是「整体颜色」，正是用户不要的。
- **实现要点**：色阶的序号即明度（50 最浅 → 1000 最深），主题用 `body` / `body[data-ds-dark-theme]`
  分别绑定浅色与深色别名。所以插件**保留构建里那条明度曲线、只替换色相与饱和度**：
  浅色模式仍与原来一样浅（只偏蓝），深色表面同深度变蓝，对比度与文字色阶无需重做。
- **代价**：只写了色相与饱和度上限（每套两个数），具体 18 档由代码按明度曲线生成 —— 想微调就改这两个数。
- **防回归**：`tools/ui-recolour-test.mjs` 直接读**已安装主题**的别名绑定，验证 ①每个栏目引用的步进、
  ②每套配色都重新着色了这些步进、③深色模式落在该色相且饱和度足够、④浅色模式仍然够浅（不会变成深蓝页面）、
  ⑤色阶保持单向。另有断言确保纯白 `bluish-00` **不**被着色、最深档**被**着色。

## ## D-10 页脚按钮：改成文字按钮，规格照抄 shell 与团队

- **决定**：`sidebar.footer.action` 里从「🖼 + 换行文字」改为**与设置/团队同规格**的按钮：外层容器 `height:42px; margin:8px 0 0`，按钮 `height:42px; border-radius:12px; gap:8px; padding:0 10px 0 8px; font-size:14px; line-height:22px`，hover 用 `--dsw-alias-interactive-bg-hover`，focus 用 2px `label-primary` 内描边；收起状态 36×36 圆形、图标 18px。图标是内联 SVG（`stroke: currentColor`），文字「壁纸」+ 右侧 token 数用省略号截断。
- **依据**：用户要求「把这个按钮换成文字并与团队的 ui 统一」。规格不是猜的 —— 从 `@wowyuarm/dsh-agent-team` 的 `TeamFooterAction` 与其 CSS module（`.YvAbSa_footerAction`）逐条读出来的。
- **代价**：emoji 换成 SVG 后**不可能**再出现「豆腐块」（原 🖼 在缺字体的环境下就渲染成方块，用户截图里正是如此）；token 数在窄侧栏可能被截断成省略号（用 `title` 兜底）。

## D-11 页脚按钮不得独占共享行（一次真实回归的修正）

- **现象（用户截图）**：新页脚按钮铺满侧栏，把隔壁的「团队」按钮挤出了可视区。
- **根因**：`sidebar.footer.action` 是**一行共享的 flex 容器**（`display:flex; width:100%; min-width:0`），我的条目是**第一个**子项。我照抄设置按钮写了 `width:100%`（设置按钮可以这么做，因为它是自己那一行的最后一个子项）+ `margin:0 -2px`，于是横向溢出，父级 `min-width:0` 不裁切 → 溢出部分把**后面的**团队按钮推出侧栏。
- **决定**：本条目改为**内容宽度**（`width:auto; max-width:100%; min-width:0`，按钮 `display:inline-flex; width:auto`），去掉负外边距，补 6px 右间距（行本身没有 gap，收起态归零以保持居中）；按钮里的长数字**隐藏**（`display:none`），数值改由作曲器下方的用量条完整呈现、并用 `title`/`aria-label` 兜底。
- **依据**：与邻居统一 ≠ 与邻居同名同宽 —— 统一的是高度、圆角、内距、字号与悬停反馈；**宽度必须服从它在共享行里的位置**。
- **代价**：页脚按钮上不再显示 token 数（此前会随数字变长而越占越宽，本身就是隐患）。
- **防回归**：`client-syntax-check` 新增 3 项断言 —— 该块与按钮块内不得出现非 `max-/min-` 的 `width:100%`、必须存在 `width:auto`、必须有 6px 间距且收起态归零。这三条正是这次踩中的规则。

## D-12 覆盖别名而不是色阶 + 控件必须自带表面（第 7 轮）

- **现象（用户截图）**：面板的会话下拉展开后是白底浅字，鼠标悬停才看得清。
- **决定 1**：改为覆盖**别名**（`--dsw-alias-bg-layer-1` / `specific-sidebar-fill` 等 8 个），不再覆盖主题的静态色阶。
  **依据**：色阶变量由主题自己的 `body` 规则声明，覆盖它是在比样式表顺序 —— 顺序不利时会**静默失效**；
  而别名覆盖是元素上的内联自定义属性，必然生效。
- **决定 2**：`--dsw-alias-bg-base` 不再强制透明。**依据**：浅色模式下那会让白卡片透出壁纸，
  「能看清」只是壁纸恰好偏暗的巧合；壁纸应当只在真正透明的表面透出。
- **决定 3**：面板内的表单控件（`select` / `option` / `input`）显式声明背景、文字、边框，并对
  `select`/`option` 设 `color-scheme: dark`。**依据**：**下拉弹层由平台绘制**，不声明表面就会用 UA 的白色；
  加上文字来自插件（浅色）→ 白底浅字。
- **代价**：面板在自己内部固定为深蓝系（含浅色主题下），这是「栏目统一深蓝」的应有之义；栏目的浅色模式则保持浅蓝纸色。
- **防回归**：①别名必须成对给出 light/dark；②四套配色须覆盖全部别名；③**WCAG 对比度断言**：面板文字对每个栏目色、
  两种模式下 ≥ 4.5:1；④控件必须声明自己的表面。

## D-13 面板层必须靠权重保持点击穿透（一次真实事故）

- **事故**：注册在 `shell.overlay` 的全屏面板层被该槽宿主规则 `.overlayLayer > * { pointer-events: auto }`
  夺走了 `pointer-events: none`，变成透明全屏挡板，把工作区选择器等控件点死（用户报障，并用「停用壁纸即可复现/消失」的对照实验确认）。
- **决定**：`.dw-surface` 使用 `pointer-events: none !important`；`.dw-card` 单独 `auto` + `z-index: 1`；
  并**撤掉** `html.dsh-wallpaper-on body > *:not(#dsh-wallpaper-layer) { position: relative; z-index: 1 }`。
- **依据**：同权重时后注入的样式表获胜，所以「穿透」必须按**最终生效**来写（权重或结构），不能按自己那行字。
  而给 `#root` 加 `z-index` 会建层叠上下文，困住应用自己的浮层 —— 壁纸层本来就是 `fixed + z-index: 0`，不需要它。
- **代价**：多两个 `!important`（有明确注释说明为什么），以及一条被删掉的规则。
- **防回归**：从**已安装的** DSH 包里读那条宿主规则做锚点 + 3 项断言，见 `CRASH-REVIEW.md` 第 10 节。

# 崩溃面审查（第 2 轮）

> 第 3 轮（删除金额）之后**重跑了本文件里的全部验证**：客户端契约 26 项、宿主接口、用量折叠两条路径、
> 崩溃测试 16 项，全绿；并在真实实例（3099）上发了 5 类恶意请求 + 非法 JSON body，进程照常 200。
> 见文末「第 3 轮复验」。

> 用户要求：「检查一下，防止 dsh 崩溃」。这一轮只做**崩溃/可用性风险**，不加功能。
> 结论先写：**没有发现能复现的崩溃向量**；已把「理论上会崩」的写法改掉，并新增了一个真进程崩溃测试。
> 必须说明的是：该测试对**加固前/加固后两种代码都通过** —— 所以它是「没找到向量」，不是「修好了一个向量」。

## 1. 审查过的三条崩溃路径

| # | 路径 | 机理 | 处理 |
|---|---|---|---|
| 1 | **未处理的 Promise 拒绝** | Node 22+ 默认 `--unhandled-rejections=throw`，进程直接退出。插件路由是 `async`，被 webServer await；若**拒绝处理分支自己再抛**（在已关闭的 socket 上 `writeHead`/`end`），异常无路可去 → 未处理拒绝 → 杀进程 | 所有响应写入经 `writable(res)` 闸门（`writableEnded`/`destroyed`/`socket.destroyed`），`sendJson` 自带 try/catch；路由统一走 `guarded()`，连失败分支也在守卫内 |
| 2 | **响应流上的未消费 `error` 事件** | 响应是 EventEmitter，`'error'` 无人监听时抛出 | `guarded()` 里对 `req`/`res` 各挂一个空 `'error'` 监听 |
| 3 | **加载期抛异常** | 插件构造函数里的 `mkdirSync` 失败（家目录只读/磁盘满）会让这一行 loader 失败 | 构造函数不再可能抛：`ensureUserDir()` 吞掉错误并返回布尔，写入路径会重试 |

## 2. 顺带修掉的真实缺陷（不是理论问题）

| 缺陷 | 影响 | 处理 |
|---|---|---|
| **浅色主题会被压成不可读** | 上一版把 `--dsw-alias-label-primary` 等文字色**硬编码成白色**，用户的浅色主题下会出现白底白字 | 改为通过 `ctx.theme.overrideTokens('dsh-wallpaper', …)` 叠加**明暗两套成对**的 token（背景/边框），**不再覆盖任何文字色**；关闭壁纸即整层撤下。`client-syntax-check` 新增 5 项断言（含「文字色必须不被覆盖」） |
| **静态壁纸传输的 fd 泄漏** | 客户端中途断开时读流不销毁，长期运行会积累描述符 | `res.on('close', () => stream.destroy())` |
| **SSE 流可能静默变僵** | 休眠/代理挂住连接后写入不报错也不结束，且从无清理 | 25 秒心跳（`: keep-alive`）顺带探测死连接；**单一定时器、`unref()`、无流时自动停** |
| **磁盘日志缓存无上限** | 长期运行会为「看过的每个会话」留一份折叠结果 | 超过 `RECENT_LOG_LIMIT × 4` 时按最近列表裁剪 |
| **请求体非法即 500** | 截断/非 JSON 的请求体被当成宿主错误 | `readJsonBody()`：读取失败 → 400，解析失败 → 400 |
| **列表期间文件消失会拖垮整个列表** | `statSync` 抛异常 → `/api/state` 500 | `fileSize()` 返回 0，消失的文件直接不出现在列表里 |
| **单个 React 面渲染失败会牵连整页** | 三个界面在同一棵树里，任一抛错会让该子树（乃至页面）崩掉 | 每个面各自包一层 `SurfaceBoundary`（`getDerivedStateFromError` → 渲染 `null`）；`apply()` 全程 try/catch，某个 slot 注册失败不影响其它两个 |
| **`apply()` 抛异常** | 会在 shell 建树期间抛出 | 样式注入、effect 注册、三个 slot 注册各自独立 try/catch；`ctx.slots` 缺失时直接跳过 |

## 4. 仍未消除的风险（诚实清单）

1. **浏览器侧没有真实页面验证**：本机无 playwright/chromium，我无法打开页面看。CSS 关键选择器是 `html.dsh-wallpaper-on body > *:not(#dsh-wallpaper-layer) { position: relative; z-index: 1 }` —— 这是**结构性**选择器，理论上会影响全局布局。若刷新后页面错乱，第一件事就是「停用壁纸」或删掉这条规则，功能不受影响。
2. **`export async function` 之外的主机面没有真实依赖校验**：`webServer` 是硬依赖（`inject`），若某个 profile 没有 web carrier，插件会停在等待态而不是崩 —— 这是 cordis 的正常语义。
3. **心跳 + SSE 的长期行为**：只做了单元/集成级验证（连开连断、取消），没有跑几小时看内存曲线。
4. **`crypto`/`fs` 的 I/O 错误**：磁盘满时写配置会抛，被 `guarded()` 兜成 500 响应，但用户会看到「保存失败」；没有做重试或降级提示。

### 第 3 轮发现的一条真实机制（重要）

**客户端 bundle 是每次请求从磁盘读的，宿主模块只在启动时 require 一次。**
所以改了 `lib/index.js` 后，**跑着的实例不会变** —— 必须重启 `dsh web`；而只改 `lib/client.js` 时，
刷新页面就够了（boot graph 每次请求重新生成）。这一条已写进 `docs/HANDOFF.md` 的坑清单。

### 第 4 轮又抓到两个真实问题

1. **`applyScheme` 没有 DOM 守卫** —— `document.documentElement.style` 在非标准文档里可能是 `undefined`，`setProperty` 会抛。虽然被 `paint` 的 try/catch 兜住不会崩，但**壁纸会整体不画**。已加守卫（样式表里本来就有同样的颜色兜底值）。
2. **旧版壁纸层只有两个子元素** —— 新增染色层后，若页面在插件更新期间重载、复用了旧层，`children[1].style` 会是错的。已加迁移：子元素少于 3 个就补上染色层。

> 附带一提：第 4 轮的测试脚手架本身出过一个 bug —— 假 `createElement` 没有像 React 那样**展平数组子节点**，导致所有 `.map()` 生成的子元素对断言不可见（选择器看起来「渲染了 0 个按钮」）。脚手架已修正，并给 `isolate()` 加了 `Surface` 调试点，让测试能直接挂载单个界面而不是反推 React 树。

## 7. 第 5 轮：页脚按钮挤掉团队按钮（布局回归，已修）

用户截图指出「你把团队的按钮挤出去了」。这不是崩溃，但属于**可用性破坏**：一个功能把另一个功能挤没了。

| 项 | 内容 |
|---|---|
| 根因 | `sidebar.footer.action` 是共享 flex 行（`display:flex; width:100%; min-width:0`）；我的条目排第一，却照抄了设置按钮的 `width:100%` + `margin:0 -2px`，横向溢出不裁切，把后面的团队按钮推出侧栏 |
| 修法 | 内容宽度（`width:auto; max-width:100%; min-width:0`）、去掉负外边距、补 6px 右间距（收起态归零）、隐藏按钮里的长数字 |
| 防回归 | 客户端断言 +3（该块内不得有非 `max-/min-` 的 `width:100%`；必须有 `width:auto`；必须有间距且收起态归零），共 **48 项** |
| 复验 | 全部套件重跑通过；真实实例（3099）serve 的 bundle 与磁盘逐字节一致，且 `width: calc(100% + 4px)` 规则已从产物中消失 |

**教训**：从邻居那里抄规格时，要区分**哪些属性是「统一」**（高度、圆角、内距、字号、悬停反馈）和**哪些属性是「服从位置」**（宽度、外边距、flex 属性）。照抄后者就是这次回归。

## 8. 第 6 轮：配色改为「换栏目颜色」，并修掉两个真实缺陷

用户澄清：「我说的调整 ui 的颜色是指这些栏目的 ui 颜色（编辑栏、会话列表…），不是指整体颜色」。
第 4–5 轮我做的整页染色层正是用户不要的东西 —— 已撤掉。

| 项 | 内容 |
|---|---|
| 做法 | 重着色主题的中性色阶 `--dsw-static-neutral-bluish-*`（编辑栏/会话列表/菜单/悬停态/插件表面的共同来源），保留**明度曲线**只换色相与饱和度 |
| 撤掉 | 画面上的 `mix-blend-mode: multiply` 染色层（`dw-tint` 元素与规则一并删除） |
| 新增验证 | `tools/ui-recolour-test.mjs`：直接读**已安装主题**的别名绑定，验证栏目引用色阶 → 配色覆盖这些步进 → 深色够蓝、浅色够浅、色阶方向正确 |
| 缺陷 1 | 色阶方向填反（深色放在浅色端）→ 浅色主题会变深蓝页面。**测试脚手架按明度判定模式后暴露**，已改为保留明度曲线 |
| 缺陷 2 | `buildRamp` 返回 `{light, dark}` 对象、消费端按 `[light, dark]` 解构 → **整层 token 静默失效**（只在 catch 里打日志，界面颜色完全不变）。客户端断言直接抓到 |
| 复验 | 客户端 52 项 / 宿主 36 项 / 配色专项 / 用量折叠两条路径 / 崩溃测试 16 项 —— 全过；真实实例 serve 的 bundle 与磁盘逐字节一致 |
| 顺带修掉的脚手架 bug | ①`$&` 未转义导致选择器转义失效；②规则解析只取第一个 `body{}`（静态色板与别名绑定是**两条**规则）；③把「模式」当成块顺序而不是按明度判定 |

> 教训：这类「颜色没生效」的故障**不会崩、不会报错**，只会看起来没变化。所以验证必须断言
> **「token 层真的叠上了、且覆盖了栏目引用的步进」**，而不是断言「代码里有这些颜色」。

## 9. 第 7 轮：白色下拉框（用户截图）与两处结构修正

用户截图：面板里的会话下拉，**展开列表是白底 + 浅色文字，鼠标悬停才看得清**。

| 项 | 内容 |
|---|---|
| 直接原因 | `<select>` / `<option>` **没有声明自己的背景**，浏览器就用 UA 默认的白色；文字颜色来自插件（浅色）→ 浅色文字压在白底上。悬停时平台把选项高亮成灰底，反而看得见 |
| 修法 | 给面板内的 `select` / `option` / 非 range 的 `input` 显式声明 `background` / `color` / `border-color`，并对 select 与 option 设 `color-scheme: dark` —— 后者不是装饰：**展开列表由平台绘制**，只有它才能让弹层跟着卡片走 |
| 结构修正 1 | 之前覆盖的是主题的**静态色阶**（`--dsw-static-neutral-bluish-*`），而主题自己也在 `body` 规则里声明同名变量 → **谁赢取决于样式表顺序**，可能静默失效。改为覆盖**别名**（`--dsw-alias-bg-layer-1` 等，组件真正消费的那层）：内联自定义属性对元素生效，永远赢，与顺序无关 |
| 结构修正 2 | `--dsw-alias-bg-base` 之前被强制成 `transparent` —— 浅色模式下白卡片也会透出壁纸，「能看清」只是因为壁纸恰好偏暗。现在 base 跟随配色，壁纸只在真正透明的表面透出 |
| 新增验证 | ①每个别名必须同时给出 **light 与 dark** 两个值（单值正是「切换配色后控件不可读」的成因）；②四套配色必须给全部别名供值；③**WCAG 对比度**：面板文字对每个栏目色、在两种模式下都必须 ≥ 4.5:1（实测最差 8.72:1）；④断言控件真的声明了自己的表面 |
| 复验 | 客户端 55 项 / 宿主 36 项 / 配色专项 / 用量折叠 / 崩溃测试 —— 全过；真实实例 serve 的 bundle 与磁盘逐字节一致 |

> 教训：**「平台绘制的部件」必须自己声明表面**（下拉弹层、原生 checkbox、滚动条）。只给文字上色、
> 把背景留给 UA，就会在某个配色下变成白底浅字 —— 而且它不报错，只是看不清。
